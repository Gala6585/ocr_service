# Сервис обработки удостоверений

Сервис принимает PDF с протоколом и удостоверениями, сопоставляет карточки с ФИО и собирает ZIP. В архив входят именные PNG, страницы протокола в PDF и отчёт Excel. Дату окончания и квалификацию вводит пользователь. Распознавание работает на CPU.

## Развёртывание на Linux

На Linux VM нужны Docker Engine с плагином Compose v2 и Python 3. Клонируйте репозиторий на VM, перейдите в его корень и выполните:

```console
python3 tools/init_env.py
docker compose build flask rq-worker streamlit
docker compose up -d --no-build
docker compose ps -a
```

Первая команда создаёт локальный `.env` со случайными паролями и выводит выбранные порты. Если файл уже есть, команда сохраняет ваши настройки. Можно также создать `.env` по образцу `.env.example` и заполнить пароли вручную. Одноразовый контейнер `migrate` применяет SQL-миграции и при успехе завершается с кодом 0.

| Сервис | Адрес по умолчанию | Доступ |
|---|---|---|
| Интерфейс | `http://localhost:8501` | `OCR_USERNAME` и `OCR_PASSWORD` из `.env` |
| pgAdmin | `http://localhost:5050` | `PGADMIN_DEFAULT_EMAIL` и `PGADMIN_DEFAULT_PASSWORD` |
| API | `http://localhost:5000/health` | Проверка состояния открыта. Маршруты `/api/` используют HTTP Basic с учётной записью сервиса |

При занятом порте скрипт подбирает следующий свободный. Фактические значения указаны в `UI_PORT`, `PGADMIN_PORT` и `API_PORT`. Эти порты доступны на локальном компьютере. Для первого запуска воркеру нужен доступ к моделям EasyOCR. После загрузки веса сохраняются в томе `ocr-models`.

Если Docker на Windows выдаёт `Temporary failure in name resolution` при установке пакетов, хотя реестры доступны с хоста, выполните `python tools/refresh_build_hosts.py` и повторите сборку. Команда создаёт локальный `compose.override.yaml` с адресами официальных реестров из DNS хоста. При изменении адресов запускайте её повторно.

На VM порты привязаны к `127.0.0.1`. Чтобы открыть интерфейс и pgAdmin со своего компьютера, поднимите SSH-туннель. Если `init_env.py` выбрал другие порты на VM, подставьте их в правой части соответствующих параметров `-L`.

```bash
ssh -N -L 8501:127.0.0.1:8501 -L 5050:127.0.0.1:5050 user@vm
```

В репозиторий входят исходники, миграции, настройки Compose, архитектура, исходный ноутбук и учебный PDF с вымышленными данными. Локальный `.env`, реальные документы, результаты, датасеты и веса OCR создаются или хранятся отдельно. Для переноса существующих заданий на VM понадобятся резервная копия PostgreSQL и соответствующий каталог `data/`.

## Обработка PDF

1. Войдите в интерфейс и откройте **Загрузить PDF**. Для первого запуска подойдёт [контрольный PDF](examples/sample.pdf). В нём первая страница содержит протокол, вторая — две учебные карточки.
2. Укажите первую и последнюю страницы протокола, считая с 1, и заполните квалификацию. Дату окончания можно оставить пустой. Для контрольного PDF диапазон равен `1–1`. При необходимости укажите индекс столбца ФИО, считая с 0.
3. Запустите обработку. В разделе **Мои задания** отображаются этап и прогресс. После завершения проверьте предупреждения, рамки и ФИО. Поддерживаются PDF до 100 МиБ, до 200 страниц, без пароля.
4. Проверяющий может выбрать карточку, исправить ФИО, строку протокола или координаты рамки и нажать **Сохранить исправления**. Воркер вырежет карточки по сохранённым координатам и пересоберёт сопоставления и архив. Номер версии позволяет обнаружить одновременные правки.
5. Нажмите **Получить архив**, затем **Сохранить ZIP**. Запрос регистрируется в PostgreSQL. Вкладка **Датасет** позволяет проверяющему отдельно сохранить исходник и подтверждённые рамки при наличии разрешения.

Начальный пользователь имеет роль `reviewer`. Для отдельного пользователя запустите `docker compose exec flask python -m service.accounts <логин> --role operator` и введите пароль в терминале. Роль `operator` позволяет обрабатывать свои документы и скачивать результат. Роль `reviewer` дополнительно разрешает править свои задания и подтверждать разметку. Та же команда задаёт новый пароль существующему пользователю.

## Просмотр данных в pgAdmin

[Схема таблиц и связей PostgreSQL](database_er.md).

Войдите в pgAdmin, откройте группу **OCR** и подключитесь к серверу **Удостоверения**. Введите `READONLY_DB_PASSWORD` из `.env` для роли PostgreSQL `ocr_readonly`. Сервер уже зарегистрирован с адресом `postgres:5432`. Таблицы находятся в **Databases → ocr → Schemas → public → Tables**. Состояние заданий видно в `jobs`, итоговые имена файлов и оценки — в `matches`, историю ручных правок — в `corrections`.

Открывайте Query Tool через контекстное меню базы **ocr** в дереве слева. Если диалог **New Connection** подставляет `16384` и сообщает, что такой базы нет, закройте диалог и откройте Query Tool из дерева базы. `16384` — внутренний идентификатор, а имя базы — `ocr`.

Пример запроса в Query Tool показывает последние обработанные карточки.

```sql
SELECT d.filename AS document, j.status, c.page_number, m.fio, m.score, m.output_file
FROM jobs j
JOIN documents d ON d.job_id = j.id
JOIN cards c ON c.job_id = j.id
JOIN matches m ON m.job_id = c.job_id AND m.card_no = c.card_no
ORDER BY j.created_at DESC, c.card_no;
```

## Файлы, сроки хранения и запуск после остановки

| Место | Содержимое |
|---|---|
| `./data/temporary/jobs/<id>/input/source.pdf` | Загруженный PDF |
| `./data/temporary/jobs/<id>/revisions/<версия>/` | Нарезки WebP без потерь, превью и каталог `output` с готовыми файлами |
| `./data/datasets/` | Разрешённые исходники и JSON с подтверждёнными координатами, номером страницы, DPI, поворотом и автором проверки |
| Тома Docker | База PostgreSQL, настройки pgAdmin, очередь Redis и веса OCR |

По умолчанию временные файлы хранятся 7 суток после обработки, после каждого запроса ZIP срок устанавливается на 24 часа от этого запроса. Для ошибочного задания срок составляет 24 часа. Настройки в секундах заданы в `.env.example`. Процесс очистки учитывает активные передачи, удаляет рабочий каталог и временные записи с ФИО, сохраняет техническую историю задания и отдельно одобренный датасет.

`docker compose stop` останавливает стек, `docker compose up -d` запускает его снова. Для диагностики используйте `docker compose logs --tail=80 flask rq-worker cleanup-worker`. Дополнительные CPU-воркеры на том же сервере можно запустить командой `docker compose up -d --scale rq-worker=2`, если хватает оперативной памяти для второй копии модели.

## API и проверка

Пример отправки документа из PowerShell. Команда запросит пароль пользователя `operator`.

```powershell
curl.exe -u operator -F "pdf=@examples/sample.pdf" -F "protocol_start=1" -F "protocol_end=1" -F "expiry_date=2030-12-31" -F "qualification=Учебная" http://localhost:5000/api/jobs
```

API отвечает `202` с `job_id`. Опрос выполняется через `GET /api/jobs/{id}`. Маршрут `GET /api/jobs/{id}/results` возвращает карточки, рамки, строки протокола и версию. Правка и подтверждение принимают эту версию. `POST /api/jobs/{id}/downloads` возвращает ZIP в теле ответа. Остальные маршруты и взаимодействие компонентов описаны в [архитектуре C4](architecture_c4_credential_service_v2.md).

Для воспроизводимой проверки работающего стека запустите `python tools/smoke.py examples/sample.pdf` с установленным пакетом `requests`. Проверка создаёт учебное задание, проверяет архив, меняет ФИО и рамку, подтверждает одну рамку и переносит учебный PDF в датасет.
